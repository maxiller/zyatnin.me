## 1. Общие сведения

### 1.1 Назначение документа

Настоящий документ определяет требования к персональному сайту-портфолио `zyatnin.me` и является основным заданием на разработку. Он описывает назначение продукта, целевую аудиторию, функциональные и нефункциональные требования, модель данных, интерфейсы, критерии приёмки и порядок развития.

Документ предназначен для использования при планировании, реализации, код-ревью, тестировании и приёмке изменений. Любое изменение поведения сайта должно быть проверено на соответствие требованиям этого документа.

### 1.2 Область применения

В область действия входят:

- статический сайт-портфолио с главной страницей и блогом;
- три языковые версии: русская, английская и иврит;
- поддержка светлой и тёмной тем;
- адаптивная вёрстка для мобильных и настольных устройств;
- генерация HTML на этапе сборки;
- публикация на GitHub Pages по домену `zyatnin.me`;
- контент, хранящийся в репозитории в виде Markdown-файлов и JSON-данных.

В область действия не входят:

- серверная часть, API и база данных;
- регистрация, аутентификация и личные кабинеты;
- электронная коммерция;
- комментарии, поиск и CMS на текущем этапе;
- мобильные приложения;
- хранение персональных данных посетителей.

## 2. Общее описание

### 2.1 Контекст продукта

`zyatnin.me` — статический сайт, который выполняет роль личной витрины инженера и площадки для технических статей. Продукт не имеет серверной логики: весь HTML генерируется заранее, а браузер получает готовые файлы с GitHub Pages.

```mermaid
flowchart LR
    VISITOR["Посетитель"] -->|HTTPS| SITE["Статический сайт zyatnin.me"]
    AUTHOR["Автор контента"] -->|git push| REPO["Репозиторий GitHub"]
    REPO -->|GitHub Actions| SITE
    SITE -->|шрифты| FONTS["Google Fonts"]
    SITE -->|"схемы статей (mermaid)"| MERMAID["CDN mermaid"]
    SITE -->|внешние ссылки| EXT["GitHub и email"]
    CRAWLER["Поисковый робот"] -->|HTTPS| SITE
```

Ключевые внешние зависимости:

- GitHub как хостинг исходников и CI;
- GitHub Pages как хостинг статики;
- Google Fonts как источник шрифтов Inter и JetBrains Mono;
- CDN mermaid как библиотека отрисовки схем в статьях (подключается лениво, только на страницах со схемами);
- внешние ссылки на GitHub и почтовый адрес.

### 3.2 Функциональные требования

Обозначения приоритетов: **Must** — без требования релиз невозможен; **Should** — важное требование; **Could** — желательное улучшение.

#### 3.2.1 Локализация и маршрутизация

| ID | Требование | Приоритет | Статус |
| --- | --- | --- | --- |
| FR-01 | Запрос `/` должен определять язык браузера (с приоритетом ручного выбора, сохранённого в localStorage) и перенаправлять на `/ru/` или `/he/`; при отсутствии совпадения и без JavaScript — на `/en/` (умолчание — английский) | Must | Реализовано |
| FR-02 | Каждая страница должна иметь языковой префикс `/ru/`, `/en/` или `/he/` | Must | Реализовано |
| FR-03 | Переключатель языка должен вести на ту же страницу другого языка с сохранением пути | Must | Частично |
| FR-04 | Каждая страница должна содержать `link rel="alternate"` для всех языков, на которых страница существует, и `x-default` | Must | Реализовано |
| FR-05 | Каждая страница должна содержать `hreflang="x-default"` | Should | Реализовано |
| FR-06 | Корневой элемент `html` должен содержать корректные `lang` и `dir` | Must | Реализовано |
| FR-07 | При отсутствии перевода переключатель не должен вести на несуществующую страницу: фолбэк на индекс раздела того же языка, затем на его главную; `hreflang` выводится только для существующих переводов (фильтры `switchLangUrl`/`altUrl`) | Should | Реализовано |
| FR-08 | URL статьи должен быть стабильным и иметь вид `/{lang}/blog/{slug}/` | Must | Реализовано |
| FR-09 | Язык контента должен совпадать с языковым каталогом | Must | Реализовано |

**Критерии приёмки для раздела:**

- При открытии `/` браузер оказывается на языковой версии, соответствующей локали браузера (умолчание — английская); ручной выбор языка сохраняется и имеет приоритет.
- Переход с `/ru/blog/container-image-consistency/` на английскую версию открывает `/en/blog/container-image-consistency/`.
- В HTML каждой страницы присутствуют `lang`, `dir` и три `hreflang`.
- Для иврита `dir="rtl"`, для русского и английского `dir="ltr"`.

## 7. Приложения

### 7.1 Контент-файл страницы

Одна страница — один файл: `content/posts/<slug>.md` для поста и `content/projects/<slug>.md` для проекта. Метаданные хранятся в нём один раз; переводимые сущности — в кусте `translations` и в теле, разделённом на три языковые ветви маркерами `<!-- lang:ru -->`, `<!-- lang:en -->`, `<!-- lang:he -->`. Из этого файла при сборке генерируются страницы всех трёх языков: имя файла, `view` и `slug` задают URL, `view` задаёт вид сайта и макет.

Пост:

```markdown
---
slug: container-image-consistency
view: dev
date: 2025-12-01
tags: [containers, ci-cd]
translations:
  ru:
    title: "От разработки до продакшена: консистентность образов контейнеров"
    excerpt: "CI/CD-практики для обеспечения идентичности OCI-образов в dev и prod средах."
  en:
    title: "From development to production: keeping container images consistent"
    excerpt: "CI/CD practices that keep OCI images identical in dev and production."
  he:
    title: "מפיתוח לפרודקשן: עקביות של תמונות מכולה"
    excerpt: "שיטות CI/CD ששומרות על זהות תמונות OCI בסביבת פיתוח ובפרודקשן."
---

<!-- lang:ru -->

<h2>Введение</h2>
<p>Текст статьи…</p>

<!-- lang:en -->

<h2>Introduction</h2>
<p>Article text…</p>

<!-- lang:he -->

<h2>מבוא</h2>
<p>טקסט המאמר…</p>
```

Проект:

```markdown
---
slug: bank-vdi
view: leader
order: 3
status: done
icon: "🖥️"
translations:
  ru:
    title: "Крупный банк"
    excerpt: "VDI для 150 000 пользователей."
    tags: [VDI, "150 000 пользователей"]
    points:
      - "Интеграция процессов технической поддержки"
  en:
    title: "Major Bank"
    excerpt: "VDI for 150,000 users."
    tags: [VDI, "150,000 users"]
    points:
      - "Integration of technical support processes"
  he:
    title: "בנק גדול"
    excerpt: "VDI ל-150,000 משתמשים."
    tags: [VDI, "150,000 משתמשים"]
    points:
      - "אינטגרציה של תהליכי תמיכה טכנית"
---

<!-- lang:ru -->
Клиент — крупный банк. Решение — VDI для 150 000 пользователей.

<!-- lang:en -->
The client is a major bank. The solution is VDI for 150,000 users.

<!-- lang:he -->
הלקוח הוא בנק גדול. הפתרון הוא VDI ל-150,000 משתמשים.
```

Метаданные — общие для всех языков страницы (правятся один раз):

| Поле | Обязательность | Тип | Правило |
| --- | --- | --- | --- |
| `slug` | Обязательно | строка | Равен имени файла без расширения, `[a-z0-9-]+`; вместе с `view` задаёт URL (DR-06, DR-07) |
| `view` | Обязательно | строка | `leader` или `dev`; задаёт вид сайта, макет и префикс URL (FR-111) |
| `translations` | Обязательно | объект | Ровно три ветви: `ru`, `en`, `he` (FR-85) |
| `date` | Обязательно для поста | дата | ISO 8601, обрабатывается как `Date`; будущая дата — отложенная публикация: статья появляется в ближайшей сборке после 00:00 UTC этого дня (FR-123) |
| `tags` | Обязательно для поста | массив | От 1 до 3 ключей `[a-z0-9-]+` из словаря `tags.names` (DR-18); подписи — в разделе [Ключи i18n](#72-ключи-i18n) |
| `order` | Обязательно для проекта | число | Позиция карточки на главной, уникальна среди проектов (FR-105) |
| `icon` | Обязательно для проекта | строка | Эмодзи для страницы проекта |
| `status` | Необязательно (проект) | строка | `done` или `in_progress`; при отсутствии бейдж статуса не выводится (FR-107) |
| `draft` | Необязательно (пост) | boolean | `true` исключает статью из сборки в любую дату (FR-89) |
| `updated` | Необязательно (пост) | дата | Дата обновления; попадает в `lastmod` sitemap и JSON-LD |

Поля языковой ветви `translations.<lang>`:

| Поле | Обязательность | Тип | Правило |
| --- | --- | --- | --- |
| `title` | Обязательно | строка | Непустой заголовок страницы на этом языке |
| `excerpt` | Обязательно | строка | Краткое описание для карточки и мета-описания; 40–200 символов для поста, непустое для проекта (DR-08) |
| `description` | Необязательно | строка | Переопределяет мета-описание |
| `cover` | Необязательно (пост) | строка | Путь к обложке |
| `tags` | Обязательно для проекта | массив | Отображаемые подписи технологий (не ключи словаря меток) |
| `points` | Необязательно (проект) | массив | Ключевые результаты проекта; выводятся списком в карточке и на странице |

Тело страницы — один раздел Markdown на язык после маркера `<!-- lang:<lang> -->`. Правила, которые проверяет сборка (`lib/content.js`, FR-125):

- каждая языковая ветвь должна присутствовать и в `translations`, и в теле ровно один раз; текст до первого маркера — ошибка;
- `slug` обязан совпадать с именем файла, `view` — с одним из двух видов, `status` — с одним из двух значений, `order` проектов не повторяется;
- неизвестное поле метаданных или перевода — ошибка: так ловится опечатка вроде `tag:` вместо `tags:`;
- `layout` и `permalink` в контент-файле не пишутся: они выводятся из `view` и `slug` (DR-03, DR-07).

Страницы генерируются шаблоном `src/content-page.njk` (пагинация по `contentModel.pages`), а данные страницы берутся из соответствующей ветви (`src/content-page.11tydata.js`). Отложенная статья и черновик в сборку не попадают вовсе: у них нет ни страницы, ни записи в коллекциях (FR-89, FR-123).

Наличие темы в обоих видах (FR-113): вид — поле одного файла, поэтому для обоих видов создаются два контент-файла с разными `slug` (и разными URL); их тексты и поля независимы.

- Набор ключей должен быть идентичен в `ru.json`, `en.json` и `he.json`.
- Строки вида не выходят за пределы своей ветви: leader-шаблон не читает `dev.*`, dev-шаблон — `leader.*`; общая строка переносится в корень, а не дублируется в двух ветвях.

- Контент проектов хранится в контент-файлах `content/projects/*.md`: имя, описание и теги проекта там, в i18n — только подписи статуса (`projects.status.*`) и интерфейсные строки (см. раздел 7.1).
- Значения `nav`, `views`, `a11y`, `footer`, `blog`, `projects`, `tags`, `leader` и `dev` обязательны и непусты.
- Список технологий для обеих витрин берётся из `site.json` (`skills[]`, DR-17).

### 7.4 Definition of Done

Изменение считается готовым, если выполнены все пункты:

- [ ] Требование имеет идентификатор в SRS и не противоречит другим требованиям.
- [ ] Критерии приёмки из раздела 4 выполнены.
- [ ] `npm run build` завершается без ошибок.
- [ ] В собранном HTML нет пустых дат, битых ссылок и неотрендеренных шаблонов.
- [ ] `npm run build` проходит самопроверку контента (`scripts/check-content.js`): каждый контент-файл соответствует модели (метаданные, три языковые ветви, метки, длина `excerpt`), все ключи i18n есть во всех языках, ветви видов не перепутаны, CSS синтаксически цел (FR-122).
- [ ] `npm run build` проходит SEO-самопроверку (`scripts/check-seo.js`): sitemap, robots, ленты, JSON-LD и метаданные соответствуют текущему контенту обоих видов и языков (FR-117).
- [ ] `title` и `description` уникальны для новых страниц.
- [ ] Мобильное меню, темы и переключение языка проверены вручную.
- [ ] Контраст и клавиатурная навигация проверены.
- [ ] Паритет ключей i18n сохранён во всех трёх языках.
- [ ] RTL-версия проверена.
- [ ] Документация и схемы обновлены при изменении модели данных.
- [ ] Для дефекта указана причина и добавлена защита от регрессии.
- [ ] Изменение прошло код-ревью.
