## 3. Правила ведения документации

1. Документация ведётся на русском языке; код, команды, имена файлов и ключей остаются в оригинальном виде.
2. Для текста используется Markdown, для схем — Mermaid.
3. Каждое требование имеет уникальный идентификатор: `FR`, `NFR`, `DR`, `IR`, `AR`, `AC`.
4. Ссылки на разделы выполняются с точным якорем заголовка.
5. При изменении модели данных одновременно обновляются [схема front matter](SRS.md#71-схема-front-matter), [ключи i18n](SRS.md#72-ключи-i18n) и [карта маршрутов](SRS.md#73-карта-маршрутов).
6. Устранённый дефект переносится из статуса «Не реализовано» в «Реализовано» только после выполнения критериев приёмки.
7. Новые требования добавляются с приоритетом MoSCoW и указанием статуса.
8. Открытые вопросы фиксируются в разделе [Открытые вопросы](SRS.md#62-открытые-вопросы) до принятия решения.
9. При любом изменении контента SEO-артефакты обновляются автоматически: `sitemap.xml`, `robots.txt`, Atom-ленты (язык × вид), JSON-LD, метаданные генерируются при сборке из тех же коллекций, что и страницы, а `npm run build` завершается ошибкой при расхождении (`scripts/check-seo.js`, требование [FR-117](SRS.md#326-seo-и-метаданные)). Новые страницы и разделы попадают в sitemap сами, если не помечены `noindex` и не исключены из коллекций.
