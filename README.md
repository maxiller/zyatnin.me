# zyatnin.me

Персональное портфолио и технический блог Макса Зятнина. Статический сайт на Eleventy с поддержкой русского, английского и иврита и двумя видами сайта — «Лидер поддержки» (светлая офисная тема) и «Разработчик» (тёмная тема в стиле IDE); публикуется на GitHub Pages.

## Быстрый старт

```bash
npm install
npm run dev
```

Сайт будет доступен по адресу `http://localhost:5000`.

| Команда | Назначение |
| --- | --- |
| `npm run build` | Сборка в каталог `_site` |
| `npm run dev` | Локальный сервер с горячей перезагрузкой |
| `npm run start` | То же, что `npm run dev` |
| `npm run covers:svg` | Обновить исходники обложек `covers/*.svg` после правки контента |
| `npm run covers:png` | Отрендерить PNG обложек опубликованных статей |
| `npm run check:covers` | Проверить, что исходники обложек соответствуют контенту |

## Контент

Одна страница — один файл: `content/posts/<slug>.md` для статьи и `content/projects/<slug>.md` для проекта. Метаданные (`slug`, `view`, `date`, `tags`, `order`, `status`, `icon`) пишутся в нём один раз — они общие для всех языков. Переводимые сущности лежат в кусте `translations` с тремя ветвями и в теле из трёх разделов с маркерами `<!-- lang:ru -->`, `<!-- lang:en -->`, `<!-- lang:he -->`.

Новая статья — один такой файл: страница всех трёх языков, карточки и ленты собираются из него. Схема полей и правила проверки — [SRS, раздел 7.1](docs/SRS.md#71-контент-файл-страницы).

## Обложки

У каждой статьи есть картинка для превью в соцсетях: 1200×630 PNG с заголовком, датой, метками и адресом на языке статьи. Она собирается в две стадии:

- **исходник** — `covers/<slug>-<lang>.svg`, коммитится. Правя статью, выполните `npm run covers:svg`; `npm run check:covers` скажет, если какой-то исходник отстал от контента (сборка это тоже проверяет).
- **картинка** — `src/assets/covers/<slug>-<lang>.png`, рендерится из исходника при каждой сборке (`npm run covers:png`) и в репозиторий не попадает. В сборку попадают только обложки опубликованных статей: у отложенной статьи исходник есть, а PNG появится в той сборке, которая её опубликует.

Слова и цвета обложка берёт из тех же данных, что и страница (заголовок, дата из `lib/dates.js`, метки из i18n, палитра вида), поэтому не может разойтись с текстом.

## Отложенные статьи

Публикация включается датой: статья с `date` в будущем не попадает в сборку и появляется в индексах, лентах и sitemap после 00:00 UTC этого дня, в ближайшей пересборке (GitHub Pages пересобирается по push и ежедневно по расписанию). `draft: true` в метаданных скрывает статью насовсем — до снятия флага. Правило одно и живёт в `lib/published.js`, а применяется один раз — при чтении контент-файла (`lib/content.js`), так что у скрытой статьи нет ни страницы, ни записи в коллекциях.

Локальный предпросмотр (`npm run dev` / `npm start`) показывает и отложенные статьи, и черновики — сервер пишет об этом строкой `[preview]` в лог. Для обычной сборки с ними: `INCLUDE_FUTURE=1 npm run build`. `npm run build` начинается с очистки `_site` (`scripts/clean.js`), поэтому страницы предпросмотра не переживают следующую сборку.
