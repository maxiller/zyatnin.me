# Проверка экшена после пуша

После любого `git push` в `origin` дождитесь завершения workflow и сообщите его результат. Пуш не считается выполненным, пока экшен не проверен.

## Что запускается

Единственный workflow — `.github/workflows/deploy.yml` («Build and Deploy to GitHub Pages»). Его триггеры:

- `push` в ветку `main` — сборка `npm run build:ghpages` (Eleventy и `scripts/check-seo.js`), затем публикация на GitHub Pages;
- `workflow_dispatch` — ручной запуск.

Пуш в любую другую ветку (`gh-pages`, ветки задач) workflow не запускает. В этом случае убедитесь, что запуска для коммита нет, и скажите об этом прямо — не ждите результата, которого не будет, и не запускайте workflow вручную без просьбы.

## Как проверить

1. Возьмите SHA отправленного коммита:

```bash
SHA=$(git rev-parse HEAD)
```

2. Найдите запуск именно для этого коммита, а не «последний вообще» — при нескольких пушах подряд легко проверить чужой:

```bash
gh run list --commit "$SHA" --limit 5 --json databaseId,status,conclusion,workflowName,headSha
```

3. Дождитесь завершения; `--exit-status` возвращает 0 при успехе и ненулевой код при падении:

```bash
gh run watch <databaseId> --exit-status --interval 10
```

4. При падении запросите только упавший шаг и его лог:

```bash
gh run view <databaseId> --log-failed
```

Если запуск ещё не появился в списке, GitHub регистрирует его с задержкой в несколько секунд — подождите и повторите шаг 2. Не создавайте лишний коммит или ручной запуск, чтобы «ускорить» проверку.

## Что сообщить

- Имя workflow, номер запуска (`databaseId`), ветку и SHA коммита.
- Итог: успех или падение, длительность, ссылку на запуск (`gh run view <databaseId> --web`).
- При падении — какой шаг упал и релевантные строки лога из `--log-failed`, без пересказа лога целиком.
- Если workflow не запускался (пуш не в `main`) — сообщите это как результат проверки.

## Ограничения

- Не изменяйте `.github/workflows/deploy.yml`, чтобы обойти упавшую проверку. Требование к конвейеру — [IR-07](../../../docs/SRS.md#35-требования-к-интерфейсам): при ошибке сборки деплой не выполняется.
- Не выполняйте `gh run rerun`, `gh run cancel` и `workflow_dispatch` без явной просьбы: они меняют состояние репозитория и публикации.
- Успешная сборка в CI — не замена локальной проверке изменений; локальную сборку по-прежнему запускайте перед пушем.
